# Xiaomi Pad 6S Pro 12.4 (sheng)

Unofficial AOSPA Calcite / Android 17 device configuration.
Product: `aospa_sheng`; release: `cp2a`; variants: `user` and `userdebug`.

## Source ownership

| Checkout | Owns |
| --- | --- |
| device/xiaomi/sheng | Tablet product, overlays, stock kernel/module layout, device services and extraction |
| device/xiaomi/sm8550-sheng-common | Tablet-family configuration, init, SELinux and common extraction |
| device/xiaomi/sm8550-platform-common | Existing shared SM8550 platform configuration and input/build helpers |
| vendor/xiaomi/sheng and vendor/xiaomi/sm8550-sheng-common | Generated proprietary inputs and vendor build metadata |

Vendor directories are generated by extraction; separate newly created vendor
GitHub repositories are not required. System/framework changes are stored as pinned patches in the existing
`vendor/xiaomi/sm8550-integration` repository, using its self-contained Sheng
profile. Upstream ROM repositories remain upstream checkouts; no individual
source forks are required for this profile.

## Proprietary and kernel inputs

Use the matching Sheng Global OS3.0.6.0.WNXMIXM / Android 16 partition dump.
Read `device-inputs.json` and its includes for the exact extra input hashes.
The kernel Image, DTB, DTBO, first-stage modules and DLKM modules must come from
one matched payload; do not combine them with Fuxi outputs. Kernel module
signatures are retained. See `tools/prepare-kernel-payload.py` for extraction.

```sh
python3 device/xiaomi/sheng/extract-files.py /path/to/stock-dump
python3 device/xiaomi/sheng/tools/extract-device-inputs.py --tree "$PWD" \
  --source /path/to/stock-dump --source /path/to/kernel-payload \
  --source /path/to/prepared-compatible-inputs \
  --built-capslock out-sheng-capslock/module/hid-nanosic-capslock.ko \
  --patchelf prebuilts/extract-tools/linux-x86/bin/patchelf-0_17_2
python3 device/xiaomi/sheng/displayfeature/apply-compat-libraries.py
python3 device/xiaomi/sheng/tools/extract-device-inputs.py --tree "$PWD" \
  --built-capslock out-sheng-capslock/module/hid-nanosic-capslock.ko --verify
```

Build the Caps Lock module before the explicit install above, as documented in
`keyboard/README.md`. It is a separate module build, not a replacement boot
kernel. Prepared compatible inputs can come from the exact previously verified
inputs; arbitrary firmware or library versions are rejected.

`extract-files.py` extracts both device/common vendor files and writes reviewed
build metadata and textual fixups from the integration repository's
`profiles/sheng/vendor-config.json`. Closed inputs
remain local. `setup-makefiles.py` uses the same extraction entry for regeneration.

## Build

After the matching upstream source checkout, extraction and input verification,
use the same preparation entry as Fuxi, selecting Sheng:

```sh
python3 vendor/xiaomi/sm8550-integration/tools/prepare-source.py --tree "$PWD" --device sheng --check
python3 vendor/xiaomi/sm8550-integration/tools/prepare-source.py --tree "$PWD" --device sheng
source build/envsetup.sh
lunch aospa_sheng cp2a user
m -j8 target-files-package
```

The existing shared `build-device.sh sheng user -j8 target-files-package` wrapper
is optional. It selects the same product/release/variant and a separate OUT_DIR;
it does not prepare a Fuxi kernel for Sheng. BUILD_NUMBER is supplied by the caller
or Android's normal defaults.

Sheng uses Android's `PRODUCT_ANDROIDMK_ALLOWLIST_FILE` to omit source DLKM make
rules while keeping UAPI/header Android.bp modules. It does not require a fork of
each kernel module merely to add a prebuilt-kernel guard. Kernel header host tools remain in the ROM graph; duplicate standalone kernel
tool checkouts are excluded. The separately built Caps Lock module uses the
matched GKI source and toolchain. Fuxi vendor and MiuiCamera projects are excluded from this product.

The 20261027 release passed full builds and basic hardware validation. That is
historical evidence; validation of this layout is recorded separately and must
not be described as a newly passed full ROM build before it actually completes.

generally Apache-2.0; kernel/module code follows its GPL/UAPI notices; closed
inputs retain their original licenses. Release signing keys are not included.
